## 资源隔离

1. 独立Supabase测试项目，加载真实现行数据库基线后执行新增迁移；不能用生产test scope冒充隔离数据库，也不能用最小夹具代替真实基线。
2. 受保护Preview，仅配置测试项目凭证；禁用生产Cron、Base Pull、生产群/表等出口。回调必须有可达且受鉴权保护的测试入口。
3. 专用飞书测试应用/机器人、测试群、测试表、授权操作人。真实按钮回调指向该Preview，不能仍指向Production。
4. 固定有序测试名单甲/乙/丙，记录每例起始游标、名单状态及版本。独立用例使用新的source/batch/request ID和测试行；同例重试保持原身份、快照及哈希。
5. 测试前后回读数据库、表格和消息；删除资源须保留审计证据，不删除故障现场制造通过结果。

| G3 | 25条连续1000676且对象不同，新策略v2，20+5两卡，两种点击顺序 | 跨20/21边界仍为一个业务组、同一人；不因卡片限制拆成两个轮转决定 |
| M1 | 点击前人工填入名单内人员，含同对象其他空行 | 人工格零PUT，保留人工人员；同组空行同人，锚点校准正确；同组两个不同人工人员必须暂停，不产生新决定/游标/写表副作用 |
| M2 | 决定落账后、写前门禁前人工填格；另测人员不在名单 | 不覆盖、不报业务成功、不重选；已落账事实保留并暂停；不能为回滚而改游标。GET→PUT之间仍非原子，绝对保护需锁负责人列/受控人工入口 |
| R1 | 点击前插行；另在决定提交后中断、插行、原卡恢复 | 按需求ID定位，不写旧行；不改快照/负责人/组计划；最新定位回读后能确认，不因旧行号永久pending。本例为当前P1必过项 |
| C1 | 至少两个独立客户端/数据库会话同时点同卡、同时点两个桶/两卡 | 唯一源计划、唯一需求assignment、仅一次组预留；pending写入不被第二writer接管；冲突明确返回，不拼接旧快照 |
| F1 | 决定提交前中断、RPC已提交但响应丢失、PUT成功但响应丢失、确认前后中断、报告/卡更新失败 | 原身份恢复；已写表先回读只补确认；无法确认进入对账并阻止相关后续卡，不新建source/改UUID/重选人员；报告失败不重做业务 |
| H1 | 改完整快照内容/顺序但保留旧哈希；重算新哈希沿用同source；代码标志/组不一致 | 全部fail-closed，不覆盖原源登记、不写表；长对象ID保持字符串 |
| L1 | 真实按钮、操作人授权、重复点击、批量更新调用数和结果卡 | 非授权零副作用；重复点击不重派；PUT批量范围使用真实定位行；业务成功必须有表格回读和持久确认，不用HTTP200冒充成功 |
| X1 | 隔离环境执行本地、AD大盘、AD游戏、应急既有用例 | 新千川策略不改其他scope、名单、游标、轮转方向和接口契约 |

G1的四条使用当前完整快照版本重新生成payload。旧下载样例只有7个决策字段，不能直接充当有效完整目标payload。
G1正反序是两个独立测试源，不能拿第一次已完成源的重放冒充反序首次处理；使用独立请求ID或恢复隔离基线。
G2/G3的“组数”不等于assignment条数；assignment按实际需求落账。
全源计划在首次点击预留是当前明确语义：未点击的卡也已预留组；不得暗中回滚这些预留。

## 故障注入边界

仅在测试部署使用经过审查的测试adapter/故障代理；不得把测试endpoint暴露到生产。
真实远端提交后丢响应/注入异常与平台实例SIGKILL不同，报告须分别标明，不得混称“真实强杀已通过”。
禁止为了测试修改生产防火墙、生产凭证、历史派单或水位线。

## 每例交付证据

- 候选SHA、Preview ID、数据库项目ID、基线/迁移哈希，执行人、时间、用例ID。
- source/delivery/request ID、冻结快照及哈希、原序列、预期组和负责人。
- 起止名单、游标/版本、assignment_seq、源计划、pending/confirmed IDs及assignment数量。
- HTTP状态及业务error_code/request_id，批量GET/RPC/PUT次数、范围及重试次数。
- 每格前后值、需求ID对应真实行、操作/message回执、群内卡片数。
- 中断精确边界、恢复动作和清理结果。凭证/claim token脱敏，不输出Secret。

## 放行标准

所有预期人员一致，原快照不可替换；不重复分配/消耗组游标，不覆盖人工格，不写错行；
未知不伪报成功，原身份可恢复或明确对账；无生产副作用，无静默串行降级。
任一P0/P1失败立即停止，保留现场，修复后重验相关矩阵，不用重复创建新批次刷通过率。
组级指定/改派尚未实现，旧单条v2入口应零副作用拒绝；本轮不宣称完整旧能力兼容。
通过后由Codex复核证据并单独申请生产发布授权；不因测试通过自动迁移、合并或切流。
