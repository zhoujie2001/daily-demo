# AD 人员状态表单：本机 HTTP 集成模拟

日期：2026-10-24。

2026-10-25 补充：真实新表单暴露了非必填多选控件的稀疏空值问题，详见 `ad-status-form-sparse-fix.md`。下面的测试记录保留为当时结果；“缺字段零 RPC”现仅适用于未保存初始状态的旧 pending。新模式按服务端打开时快照保留未提交名单，不自动清空。

## 结论边界

这是一组可复现的本机集成模拟，不是真实飞书客户端、Vercel Preview 或真实 Supabase/PostgREST 验收。它不自动替代用户要求的隔离环境真实表单发布门禁。

真实执行的应用代码包括：

- `api/lark/callback.js` 的 HTTP 方法、JSON 解析、verification token/app_id 鉴权、500ms 响应期限及延迟收尾；
- `LarkClient` 的 Token、消息回复和卡片更新 HTTP 序列化；
- `createSupabaseDispatchStore` 的请求路径、过滤条件、RPC 参数和错误映射；
- 状态表单渲染、真实按钮 value、服务端 pending 恢复、三名单更新和回调路由。

明确模拟的边界包括：

- 飞书 Token、回复消息、卡片更新服务；
- PostgREST 数据接口和 RPC 的服务端事务行为，后端使用内存 store；
- 飞书客户端本身、数据库 SQL/RLS/ACL、跨实例并发、Vercel 冷启动及网络可达性。

请求只允许访问本轮 `127.0.0.1` 随机端口。环境变量仅在测试进程内临时替换，随后恢复；不读取生产密钥、不访问生产服务、不发送真实卡片或修改水位线。未实现的模拟接口直接报错，不允许静默假成功。

## 复现

```sh
node --test --test-reporter=spec tests/statusFormHttpIntegration.test.js
```

若 Windows 沙箱阻止本机回环连接，需要允许该测试进程访问回环网络；不能把 `EACCES 127.0.0.1` 误判为业务失败，也不能通过跳过测试报通过。

## 14 个场景

1. 带真实按钮 value 的表单保存、重复回调只提交一次。
2. 仅 form_value 的兼容路径保存、重复回调只提交一次。
3. 三个显式空数组允许主动清空。
4. 缺少 AD 大盘字段，零状态 RPC。
5. 缺少 AD 游戏字段，零状态 RPC。
6. 缺少应急需求字段，零状态 RPC。
7. 旧 pending 协议拒绝且保留原离岗状态。
8. 两个真实渲染表单使用同一 CAS 快照，后提交者冲突且不覆盖。
9. 错误 verification token 在访问数据库/飞书前返回 403。
10. 错误 app_id 在访问数据库/飞书前返回 403。
11. 跨群回调拒绝且保留三份名单。
12. 完成标记回执失败后，使用原 operation 重放，不再增加版本。
13. RPC 已提交、HTTP 回执断开后，使用原 operation 恢复，不再次提交状态。
14. RPC 延迟超过回调响应期限，先返回处理中，随后更新成功卡。

成功保存同时核验游标及 assignment sequence 不变。卡片断言覆盖三份名单名称；本地模拟不代表飞书实际渲染和交互行为已被观察。
